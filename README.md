# PipDimmer — Chrome 子母畫面滾輪透明控制器

[English](README.en.md)

游標移到 Chrome 子母畫面（Picture-in-Picture）上，**直接滾滑鼠滾輪就能調它的透明度**。
其他視窗按住 Ctrl+Shift 再滾也可以。Ctrl+Shift+中鍵能把視窗變成點得過去的「幽靈視窗」。

功能上對標 Spooky View / WindowTop，但辨識子母畫面的方式不靠視窗標題（不會被語系綁死），
而且完全免安裝、免系統管理員權限、單一 45 KB 執行檔。

需求：Windows 10 1703 以上（.NET Framework 4.x 為系統內建，不需另外安裝）。

---

## 快速上手

到 [Releases](../../releases) 下載 `PipDimmer.exe`，雙擊即可——會常駐系統匣，
不會寫登錄檔，也不需要系統管理員權限。

| 操作 | 效果 |
|---|---|
| 游標在**子母畫面**上，直接滾滾輪 | 調整該視窗透明度 |
| 游標在**其他視窗**上，**Ctrl+Shift**+滾輪 | 調整該視窗透明度 |
| 游標在其他視窗上，滾輪或 **Ctrl**+滾輪 | **完全不受影響**——正常捲動、瀏覽器縮放照常 |
| **Ctrl+Shift+中鍵** | 切換滑鼠穿透（幽靈視窗）；再按一次關閉 |
| 系統匣圖示**左鍵單擊** | 快速啟用／停用 |
| 系統匣圖示**右鍵** | 完整選單 |

預設每格 5%，最低 10%，滾輪上=更不透明、下=更透明。

### 為什麼修飾鍵是 Ctrl+Shift 而不是單獨 Ctrl

`Ctrl+滾輪` 在瀏覽器、VS Code、檔案總管、Office 都是**縮放**；`Ctrl+中鍵` 在瀏覽器是
**在新分頁開啟連結**。拿它們當透明度控制會把這些功能整個蓋掉。

`Win` 和 `Alt` 雖然只要一個鍵，但放開時會分別觸發**開始功能表**和**選單列**——除非額外
注入遮罩按鍵，用起來會很煩（選單裡仍然可以選，C# 版有做遮罩處理）。
`Shift+滾輪` 在瀏覽器和檔案總管是水平捲動。

`Ctrl+Shift` 左手同側好按，而且幾乎沒有程式在用。想換成別的，系統匣 →
**修飾鍵（其他視窗）** 有 8 種可選，改完立即生效。

> 啟動時**不會**動到已經開著的視窗。只有之後**新開**的子母畫面才會自動套用上次的透明度。

## 兩個版本

| | `PipDimmer.exe`（主要） | `ahk\PipDimmer.ahk` |
|---|---|---|
| 需要安裝什麼 | 什麼都不用（.NET Framework 是 Windows 內建） | 需要 AutoHotkey v2 |
| 可以複製到別台機器 | 可以，單一檔案 | 需對方也裝 AHK |
| 改參數 | 系統匣選單 / `settings.ini` | 同左，另可直接改腳本 |
| 建議 | **平常用這個** | 想自己改邏輯時用這個 |

兩個版本共用同一份 `%APPDATA%\PipDimmer\settings.ini`，格式一模一樣。
**不要同時執行兩個**，否則會互搶同一個視窗。

## 系統匣選單

| 項目 | 說明 |
|---|---|
| **啟用** | 總開關。關掉後所有滾輪行為完全放行 |
| **每格步進** | 一格滾輪改變幾 %（2 / 5 / 10） |
| **最低透明度** | 能調到的最透明程度（10 / 20 / 30%）。硬性下限是 10%，因為 alpha 歸零會讓視窗**點不到也抓不回來** |
| **修飾鍵（其他視窗）** | 調整非子母畫面視窗時要按的鍵：無 / Shift / Alt / Win / Ctrl / **Ctrl+Shift**（預設）/ Ctrl+Alt / Shift+Alt。只影響其他視窗，子母畫面永遠是直接滾 |
| **顯示 OSD 百分比** | 游標旁浮現「子母畫面 65%」小提示，0.85 秒後消失 |
| **新的子母畫面自動套用上次透明度** | 換一支影片、重開子母畫面時不用重滾 |
| **允許 <修飾鍵>+滾輪 調整其他視窗** | 關掉後就只管子母畫面 |
| **<修飾鍵>+中鍵 切換滑鼠穿透** | 關掉後中鍵行為完全不受干擾 |
| **反轉滾輪方向** | 改成滾輪上=更透明 |
| **套用後強制重繪** | 萬一某個程式套用後畫面不更新才需要打開，平常不用 |
| **還原所有視窗** | 一鍵把所有被動過的視窗變回不透明、取消穿透 |
| **偵測視窗資訊…** | 倒數 3 秒後抓游標下的視窗，列出 class / 標題 / 程序 / style / exstyle，**並說明它為什麼沒被判定成子母畫面**。偵測出問題時先用這個 |
| **重新掛載滑鼠鉤子** | 滾輪突然沒反應時按這個 |
| **開機自動啟動** | 在「啟動」資料夾建捷徑，不需管理員、不碰登錄檔 |
| **結束** | 結束前會把所有動過的視窗還原 |

## 「滑鼠穿透」是什麼

技術上是給視窗加上 `WS_EX_TRANSPARENT`：讓它對滑鼠「不存在」——點擊、滾輪、拖曳全部
**穿過去**打到底下的視窗。視窗你還是看得見（透明度是另一回事），但它不再接受任何滑鼠操作，
變成純粹的浮層。

實際用途：把子母畫面調到半透明**又**開穿透，就能直接把它壓在你正在編輯的文件上——
影片看得到，同時照常在底下的文件點選、打字，完全當它不存在。這就是 Spooky View 的招牌
「幽靈視窗」。

代價是你也點不到它了（不能拖動、不能關）。PipDimmer 把穿透中的視窗記在自己的清單裡、
改用座標比對找回它，所以**滾輪仍然調得動透明度**，再按一次同樣的手勢就關掉穿透。

## 它怎麼認出子母畫面

不是比對「子母畫面」這四個字。實際量到的資料是：

| 視窗 | style | exstyle |
|---|---|---|
| **子母畫面** | `0x16CC0000` | `0x00200108` |
| 一般 Chrome 視窗 | `0x36CF0000` | `0x00200100` |
| Chrome `--app` 視窗 | `0x16CF0000` | `0x00200100` |

判斷條件（全部要成立）：

1. 視窗類別是 `Chrome_WidgetWin_1`
2. 程序是 chrome / msedge / brave / vivaldi / opera / chromium / thorium 其中之一
3. 有 `WS_EX_TOPMOST`（置頂）— 子母畫面永遠置頂，一般瀏覽器視窗不是
4. **沒有** `WS_EX_NOACTIVATE` — 排除 Chrome 的提示泡泡、自動填入下拉這類點不到的暫時覆蓋層
5. **沒有同時具備**最小化鈕和最大化鈕 — 一般瀏覽器視窗兩個都有，子母畫面兩個都沒有
6. 尺寸至少 120×80

第 5 點是防止「你用別的工具把一般 Chrome 視窗設成置頂」時被誤判——那會害那個視窗的滾輪被吃掉。
如果哪天 Chrome 改版讓子母畫面長出了這兩個鈕，在 `settings.ini` 設 `RequirePipShape=0` 即可。

另外還有一條**備援路徑**：標題精確符合各語系的子母畫面名稱時（子母畫面 / 画中画 /
Picture in picture / ピクチャー イン ピクチャー / PIP 모드 / Bild im Bild /
Imagen en imagen / Mode PIP…）也算數。這串字跟著**瀏覽器**的介面語言走，不是作業系統語言。

> YouTube 迷你播放器、Google Meet 用的是 **Document PiP**，它的視窗標題是網頁標題而不是
> 「子母畫面」，所以只能靠第 1～6 點的結構特徵命中。

## settings.ini

位置：`%APPDATA%\PipDimmer\settings.ini`（純文字，key=value）

| 鍵 | 預設 | 說明 |
|---|---|---|
| `Enabled` | 1 | 總開關 |
| `StepPercent` | 5 | 每格 %（只接受 2 / 5 / 10） |
| `MinPercent` | 10 | 最低透明度（只接受 10 / 20 / 30） |
| `LastAlphaPercent` | 60 | 上次用的值，供「自動套用」使用 |
| `ShowOsd` | 1 | OSD 百分比提示 |
| `AutoApply` | 1 | 新子母畫面自動套用 |
| `AllowOtherWindows` | 1 | 修飾鍵+滾輪可調其他視窗 |
| `GhostGesture` | 1 | 修飾鍵+中鍵切換穿透 |
| `ModifierMask` | 3 | 修飾鍵位元遮罩：`1`=Ctrl `2`=Shift `4`=Alt `8`=Win，相加；`0`=不需修飾鍵。預設 3 = Ctrl+Shift |
| `InvertWheel` | 0 | 反轉滾輪方向 |
| `ForceRedraw` | 0 | 套用後強制重繪 |
| `RequirePipShape` | 1 | 見上一節第 5 點；只有偵測失敗時才改成 0 |

## 疑難排解

**滾輪沒反應**
1. 系統匣 →「偵測視窗資訊…」，把游標放到子母畫面上，看它判定成什麼、以及沒命中的原因。
2. 系統匣 →「重新掛載滑鼠鉤子」。Windows 會在低階鉤子逾時太多次後**靜默**把它拔掉，
   而且程式無從得知；PipDimmer 有看門狗會自動重掛，但手動這一項是保險。
3. 如果目標程式是用**系統管理員身分**開的，UIPI 會擋住一般權限的程式，這是 Windows 的
   安全機制，沒有繞法。改用一般權限開那個程式即可（Chrome 平常不需要提權）。

**畫面變黑 / 套用後不更新**

實測 Chrome 子母畫面（含 `WS_EX_NOREDIRECTIONBITMAP`）在 Windows 11 上完全正常，
但如果你在別的程式上遇到：

1. 系統匣 → 勾選「套用後強制重繪」
2. 還是不行的話：Chrome 設定 → 系統 → 關閉「使用硬體加速模式」（代價是影片解碼走軟體）

**跟其他透明度工具打架**

Spooky View、WindowTop 這類工具同樣會去改視窗的 `WS_EX_LAYERED`，
同時開著可能互相覆蓋。建議同一時間只留一個。

**程式當掉後視窗還是半透明**

系統匣「還原所有視窗」；或直接把那個子母畫面關掉重開。
正常結束（選單「結束」或登出）一定會還原。

**診斷記錄**

```
PipDimmer.exe -log
```
會把鉤子掛載結果、每秒掃描到的子母畫面、每次滾輪動作寫到
`%APPDATA%\PipDimmer\log.txt`。平常不需要開。

## 重新建置

```powershell
.\build.ps1
```

用的是 Windows 內建的 C# 編譯器
（`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`），不需要 .NET SDK 或 Visual Studio。

> ⚠️ 那顆編譯器是 **Roslyn 之前的 C# 5.0** 版本。改 `src\PipDimmer.cs` 時不能用字串內插
> `$"..."`、`?.`、`nameof`、expression-bodied members、`out var`。build.ps1 已經寫死
> `/langversion:5`，用到就會在編譯期直接報錯。

> ⚠️ `build.ps1` 刻意全英文。Windows PowerShell 5.1 讀 `.ps1` 時若檔案沒有 UTF-8 BOM
> 會改用系統 ANSI 編碼（繁中系統是 Big5），非 ASCII 字元會變亂碼並產生語法錯誤。
> `PipDimmer.ahk` 則帶 BOM，所以中文沒問題。

## 已知限制

- 提權（系統管理員）視窗無法調整，也收不到它上面的滑鼠事件——這是 Windows UIPI 的設計。
- 子母畫面上的滾輪會被攔截，所以 Chrome 自己若有滾輪功能會失效（目前的子母畫面沒有）。
  真的需要的話，在系統匣把「啟用」關掉，或把修飾鍵設成非「無」的值後只用修飾鍵操作。
- Document PiP 的視窗在 Windows 上可能帶 `WDA_EXCLUDEFROMCAPTURE`（不出現在螢幕擷取中），
  這不影響透明度，但截圖會看到黑塊。
- 幽靈（穿透）視窗會從 `WindowFromPoint` 消失，PipDimmer 靠自己維護的清單用座標找回它，
  所以穿透後仍能用滾輪調回來。但如果 PipDimmer 被強制結束（非正常結束），
  那個視窗會維持穿透狀態，需要重開該視窗。
